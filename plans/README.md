## Design decisions carried into every plan

* Hugo’s default app chrome is monochrome: `.primary` is black in Light Mode and white in Dark Mode. Native dynamic system backgrounds and label hierarchy remain the base palette.
* `.hugoAccent` is System Teal and is strictly opt-in: progress gauges, primary CTAs, active status/completion markers, and fallback category colors only.
* Category-specific colors are content data, not chrome. Existing persisted tracker color channels may be rendered only when they represent a valid assigned color; otherwise use `.hugoAccent`.
* Editorial typography uses Apple’s built-in New York serif through `Font.Design.serif`; interface typography stays on the default San Francisco design. No bundled custom font is required.
* Existing rounded card geometry is retained. Do not change corner radii or replace native/system backgrounds unless a plan explicitly says to do so.

* V11 report handling: one aggregate Field Service line plus one line per separate category, each with its own rounding rule and no default. Transfers become generated next-month entries; carry-in is never read from `carriedOutSeconds`. Year totals use submitted hours for submitted months, entry sums otherwise.

## Findings considered and rejected

* **Converting the V9→V10 stage to `.custom`**: not part of this release; V10 has already shipped and the stage is unchanged. Revisit only with a failing upgrade report.
* **Stable UUID identity for categories in reports**: deferred; requires a new schema version. Name-keyed lines are a documented limitation (plan 032).
* **Replacing `nonisolated(unsafe)` migration staging statics**: deferred; migrations run once, serially, at container creation.
* **Non-editable visual style for generated entries**: owner-owned follow-up, not planned here.

* **The supplied `Color.hugoAccent` implementation delegating with `.hugoAccent`**: rejected because Swift resolves that expression to the same `Color` property, emits an infinite-recursion warning, and crashes at runtime. Plan 027 uses the safe reverse delegation: `Color.hugoAccent` returns `.teal`; the constrained `ShapeStyle` overload returns `Color.hugoAccent`.
* **Adding a category color picker and a new SwiftData schema migration now**: deferred. The request establishes a color architecture and fallback behavior, but it does not specify a color-selection UX or a persisted model contract. Plan 029 uses the current V8-compatible `hue`, `sat`, and `bri` channels read-only and introduces no schema change.
* **Keeping the legacy Orange `AccentColor` asset as a fallback**: rejected. It can reintroduce Orange in a scope that does not inherit SwiftUI’s root tint, contradicting the neutral baseline. Plan 027 removes the build-setting references and unused asset.
* **Changing the monthly hero’s whole-hour formatting to fractional hours**: deferred. The `14.5` example establishes the intended typographic role, not a reporting-format rule. Existing `Int(value)` behavior remains unchanged until product requirements define rounding, locale, and accessibility wording for fractional display.
* **Bundling a custom serif typeface**: rejected. iOS 26 provides New York through `.system(_, design: .serif, weight:)`, which honors Dynamic Type and avoids font-resource maintenance.
