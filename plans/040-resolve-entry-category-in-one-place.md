## Why this matters

Each `Entry` has a live link to its category (`entry.tracker`, a `Tracker`) and a copy of the category's name, icon and type taken when the entry was created (`entry.storedTracker`). The copy exists so an entry still counts correctly after its category is deleted. Six places in the app work out "which category is this entry" in different ways, and three of them ignore the copy:

- Minutes carried into a month by the "transfer" rounding rule are stored as generated entries with no live category and a copy only. The Overview breakdown and the entry rows show them as "Unknown Service" with a "?" icon, while the report and Year screens file them under Field Service. Every user who picks "transfer" sees this every month.
- An entry from a deleted category shows three different names on three screens.
- The copy is never refreshed. If a user moves an entry from "Bethel" (separate) to "Field Service" (main) and later deletes "Field Service", the entry falls back to the old "Bethel" copy and silently moves between report lines.

After this plan, one function resolves the category for every screen, and the copy is refreshed whenever it could become wrong.

## Steps

### Step 1: Add the resolver

Create `Hugo/Features/Entries/EntryCategory.swift`:

```swift
import Foundation

/// The category an entry counts toward. Resolved from the live `Tracker`
/// first, then the `storedTracker` snapshot (kept so entries survive their
/// category being deleted), then an "untracked" fallback.
nonisolated struct EntryCategory: Hashable {
    /// Grouping key: the tracker's UUID string, `stored:<name>|<icon>|<type>`
    /// for a snapshot, or `untracked`.
    let key: String
    let name: String
    let iconName: String
    /// `nil` only for an untracked entry.
    let type: TrackerType?
    /// Set only when the live tracker is attached.
    let trackerID: UUID?
}

extension Entry {
    nonisolated func resolvedCategory(locale: Locale = .current) -> EntryCategory {
        if let tracker {
            return EntryCategory(
                key: tracker.id.uuidString, name: tracker.name, iconName: tracker.iconName,
                type: tracker.type, trackerID: tracker.id)
        }
        if let snapshot = storedTracker {
            return EntryCategory(
                key: "stored:\(snapshot.name)|\(snapshot.icon)|\(snapshot.type.rawValue)",
                name: snapshot.name, iconName: snapshot.icon, type: snapshot.type, trackerID: nil)
        }
        return EntryCategory(
            key: "untracked", name: String(localized: "entry.untracked", locale: locale),
            iconName: "questionmark.circle", type: nil, trackerID: nil)
    }
}

extension Entry {
    /// Copies the live tracker's current name, icon and type into the snapshot.
    /// Does nothing when no tracker is attached.
    func refreshStoredTracker() {
        guard let tracker else { return }
        storedTracker = EntryTracker(name: tracker.name, icon: tracker.iconName, type: tracker.type)
    }
}
```

### Step 6: Refresh snapshots when they could go stale

1. Create `Hugo/Features/Categories/CategoryDeletionService.swift`:

   ```swift
   import Foundation
   import SwiftData

   @MainActor
   struct CategoryDeletionService {
       private let context: ModelContext

       init(context: ModelContext) {
           self.context = context
       }

       /// Deletes a category. Each entry's snapshot is refreshed first, so the
       /// entry keeps counting toward the category's latest name and type.
       func delete(_ tracker: Tracker) throws {
           for entry in tracker.entries ?? [] {
               entry.refreshStoredTracker()
           }
           context.delete(tracker)
           try context.save()
       }
   }
   ```

## Maintenance notes

- New code that needs an entry's category must call `entry.resolvedCategory()`. Do not read `entry.tracker` directly for display or grouping.
- The Overview merges a snapshot into a live category only on exact `name` and `type` match. Generated Field Service carry entries are named with the `category.default.label` string ("Field Service" in English, "Tjeneste" in Danish), while the seeded default category uses `tracker.fieldservice.name` ("Forkyndelse" in Danish). In Danish the carried minutes therefore show as their own "Tjeneste" row. Aligning those two strings is an owner decision about naming, not part of this plan.
- Snapshots are refreshed only on re-categorize and on delete, not on every rename. That is enough because the snapshot is read only after the live tracker is gone. If a future feature reads snapshots while the tracker exists, refresh on rename too.
- Plan 041 merges duplicate categories that share one `id`. It re-points entries to the surviving tracker; it should call `refreshStoredTracker()` on moved entries.
